Design Section 6: Autonomous QA Session (HelixQA Core)

The new test type — SessionCoordinator, PlatformWorkers, and 4-phase execution

Session Lifecycle — 4 Phases
Phase 1: Setup (Sequential)
1.1 Load .env configuration
1.2 LLMsVerifier.VerifyWithStrategy(ctx, QAStrategy) → ranked models
1.3 DocProcessor.LoadDir(ctx, projectRoot) → documents
1.4 DocProcessor.BuildFromDocs(ctx, docs) → feature map
1.5 DocProcessor.Enrich(ctx, featureMap, agent) → refined map
1.6 LLMOrchestrator.SpawnAgents(ctx, selectedModels) → agent pool
1.7 VisionEngine.Init(ctx, visionProvider) → analyzer
1.8 Start video recording for each platform
1.9 Emit SessionStarted event with timestamps
Phase 2: Documentation-Driven Verification (Parallel per Platform)
For each platform (Android, Desktop, Web) in parallel:

2.1 PlatformWorker acquires Agent from pool
2.2 For each Feature in FeatureMap (priority order):
    a. Agent receives: "Verify feature: {name}. Steps: {steps}"
    b. For each TestStep:
       - VisionEngine captures screenshot (pre-action)
       - Agent analyzes screen → decides action
       - ActionExecutor performs action on app
       - VisionEngine captures screenshot (post-action)
       - VisionEngine.CompareScreens() → diff
       - Agent evaluates: did the expected outcome happen?
       - CoverageTracker.MarkVerified() or MarkFailed()
       - Session.RecordEvent(timestamp, screenshot, action, result)
    c. If issue found → IssueDetector creates ticket
2.3 NavigationGraph updated with each screen transition
2.4 Detector checks for crashes/ANRs after each action
Phase 3: Curiosity-Driven Exploration (Parallel per Platform)
For each platform in parallel:

3.1 Agent receives NavigationGraph + "explore undiscovered areas"
3.2 Exploration loop (until timeout or coverage target):
    a. VisionEngine captures current screen
    b. Agent sees: screen analysis + navigation graph + "what haven't we tried?"
    c. Agent decides: click unexplored button / try edge case / go deeper
    d. ActionExecutor performs action
    e. VisionEngine analyzes result → new screen? issue? crash?
    f. NavigationGraph.AddScreen() if new
    g. IssueDetector evaluates UX: confusing navigation? broken layout?
    h. Session.RecordEvent()
3.3 Agent tries edge cases: empty inputs, rapid clicks, back button, rotation
3.4 Undocumented features found → flagged for doc update
Phase 4: Report & Cleanup (Sequential)
4.1 Stop all video recordings
4.2 CoverageTracker.Coverage() → coverage report
4.3 NavigationGraph.Export() → navigation map (DOT/Mermaid)
4.4 Aggregate all tickets across platforms
4.5 Link ticket screenshots to video timestamps
4.6 Generate QA report (Markdown + HTML + JSON)
4.7 LLMOrchestrator.Shutdown() → release all agents
4.8 Emit SessionCompleted event with summary

// ═══ Session Coordinator ═══
type SessionCoordinator struct {
  config        *SessionConfig
  verifier      LLMsVerifierClient // calls LLMsVerifier
  docProcessor  DocProcessorClient // calls DocProcessor
  orchestrator  AgentPool // from LLMOrchestrator
  visionEngine  Analyzer // from VisionEngine
  featureMap    *FeatureMap
  workers       map[string]*PlatformWorker
  phaseManager  *PhaseManager
  session       *SessionRecorder
  mu            sync.Mutex
}
func (sc *SessionCoordinator) Run(ctx) (*SessionResult, error)
func (sc *SessionCoordinator) Pause(ctx) error
func (sc *SessionCoordinator) Resume(ctx) error
func (sc *SessionCoordinator) Cancel(ctx) error
func (sc *SessionCoordinator) Status() SessionStatus
func (sc *SessionCoordinator) Progress() ProgressReport
// ═══ Platform Worker ═══
type PlatformWorker struct {
  platform      string // android, desktop, web
  agent         Agent
  analyzer      Analyzer
  navigator     *NavigationEngine
  issueDetector *IssueDetector
  coverage      CoverageTracker
  navGraph      NavigationGraph
  detector      CrashDetector // existing HelixQA detector
  session       *SessionRecorder
}
func (pw *PlatformWorker) RunDocDriven(ctx, features []Feature) ([]StepResult, error)
func (pw *PlatformWorker) RunCuriosityDriven(ctx, timeout time.Duration) ([]StepResult, error)
// ═══ Phase Manager ═══
type PhaseManager struct {
  phases    []Phase
  current   int
  listeners []PhaseListener
  mu        sync.Mutex
}
type Phase struct {
  Name     string // "setup", "doc-driven", "curiosity", "report"
  Status   PhaseStatus // pending, running, completed, failed, skipped
  StartAt  time.Time
  EndAt    time.Time
  Progress float64 // 0.0 - 1.0
  Error    error
}
// ═══ Session Result ═══
type SessionResult struct {
  SessionID     string
  StartTime     time.Time
  EndTime       time.Time
  Duration      time.Duration
  Phases        []Phase
  Coverage      CoverageReport
  NavigationMap GraphSnapshot
  Tickets       []Ticket
  Videos        map[string]string // platform → video path
  Screenshots   []Screenshot
  PlatformResults map[string]*PlatformResult
  LLMsUsed      []ModelInfo
  ReportPath    string
  Success       bool
}

Issue detection categories:
• Visual bugs: overlapping elements, truncated text, broken layouts
• UX issues: confusing navigation, dead ends, inconsistent behavior
• Accessibility: low contrast, missing labels, small touch targets
• Functional: features not working as documented, unexpected errors
• Performance: slow transitions, unresponsive UI, long loading
• Crashes: ANRs, app closures (via existing HelixQA detector)
