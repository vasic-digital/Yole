Test Infrastructure Patterns
// ═══ Mock LLM Server (for deterministic E2E tests) ═══
All modules ship a testutil/ package with:

• MockAgent — implements Agent interface, returns canned responses
• MockVisionProvider — returns preset ScreenAnalysis for test images
• MockLLMServer — HTTP server returning scripted responses
• MockActionExecutor — records actions without real UI interaction
• TestFixtures — sample screenshots, docs, .env files, YAML banks

Key principle: No test requires real LLM API calls or real devices.
All external dependencies are mocked. Tests run in CI without API keys.
Integration tests use real file I/O but mock all network/LLM/device calls.
// ═══ Test Naming Convention ═══
*_test.go — unit tests (same package)
*_integration_test.go — cross-package integration
*_e2e_test.go — full pipeline end-to-end
*_security_test.go — security-focused tests
*_stress_test.go — concurrent/load/performance
*_automation_test.go — CI/build/release validation

All tests run with: go test ./... -race -count=1
All tests tagged: // +build !integration for fast unit-only runs
