Design Section 3: LLMOrchestrator Module

Headless CLI agent management with hybrid pipe+file communication

Core Interfaces
// ═══ Agent Interface ═══
type Agent interface {
  ID() string
  Name() string // "opencode", "claude-code", "gemini", etc.
  Start(ctx) error
  Stop(ctx) error
  IsRunning() bool
  Health(ctx) HealthStatus
  // Real-time interaction (stdin/stdout pipe)
  Send(ctx, prompt string) (Response, error)
  SendStream(ctx, prompt string) (<-chan StreamChunk, error)
  // File-based exchange (artifacts)
  SendWithAttachments(ctx, prompt, []Attachment) (Response, error)
  OutputDir() string
  // Capabilities
  Capabilities() AgentCapabilities
  SupportsVision() bool
  ModelInfo() ModelInfo // from LLMsVerifier
}
// ═══ Agent Pool ═══
type AgentPool interface {
  Register(agent Agent) error
  Acquire(ctx, requirements AgentRequirements) (Agent, error)
  Release(agent Agent)
  Available() []Agent
  HealthCheck(ctx) []HealthStatus
  Shutdown(ctx) error
}
// ═══ Response Parser ═══
type ResponseParser interface {
  Parse(raw string) (ParsedResponse, error)
  ExtractJSON(raw string) (map[string]any, error)
  ExtractActions(raw string) ([]Action, error)
  ExtractIssues(raw string) ([]Issue, error)
}

Hybrid Communication Protocol
═══ Real-time Channel (stdin/stdout pipes) ═══
Used for: navigation commands, screen analysis, quick decisions
→ Send: {"type":"prompt","content":"What do you see on this screen?","image_path":"/tmp/screenshot.png"}
← Recv: {"type":"response","content":"I see a login form with...","actions":[{"type":"click","target":"username_field"}]}
→ Send: {"type":"prompt","content":"Navigate to Settings > About"}
← Recv: {"type":"response","content":"Opening settings...","actions":[{"type":"click","target":"settings_icon"}]}
═══ File-based Channel (shared directory) ═══
Used for: screenshots, analysis reports, ticket drafts, large context
/tmp/helix-session-{id}/
  ├─ inbox/ ← HelixQA writes instructions here
  │  ├─ 001-analyze-screen.json

  ├─ outbox/ ← Agent writes results here
  │  ├─ 001-analysis.json
  │  ├─ 001-ticket-draft.md
  │  └─ 002-feature-coverage.json

Key Design Decisions

  • BaseAdapter — shared process management (spawn, pipe setup, graceful shutdown, timeout). Each CLI adapter only implements the protocol-specific parsing.
  • AgentPool — mutex-safe, supports Acquire(ctx, requirements) to get an agent matching capability needs (e.g., "needs vision"). Blocks if none available, respects context cancellation.
  • Circuit breaker per agent — if an agent crashes 3 times in a row, it's marked unhealthy and excluded from the pool until manual reset or health check passes.
  • No LLMsVerifier dependency at Go module level — LLMOrchestrator accepts ModelInfo structs passed in by HelixQA. The LLMsVerifier selection happens before LLMOrchestrator is initialized.
