Design Section 4: VisionEngine Module

GoCV core operations + LLM Vision for intelligent UI understanding

Core Interfaces
// ═══ Vision Analyzer — Primary Interface ═══
type Analyzer interface {
  AnalyzeScreen(ctx, screenshot []byte) (ScreenAnalysis, error)
  CompareScreens(ctx, before, after []byte) (ScreenDiff, error)
  DetectElements(screenshot []byte) ([]UIElement, error)
  DetectText(screenshot []byte) ([]TextRegion, error)
  IdentifyScreen(ctx, screenshot []byte) (ScreenIdentity, error)
  DetectIssues(ctx, screenshot []byte) ([]VisualIssue, error)
}
// ═══ Navigation Graph ═══
type NavigationGraph interface {
  AddScreen(screen ScreenIdentity) string // returns node ID
  AddTransition(from, to string, action Action)
  CurrentScreen() string
  SetCurrent(screenID string)
  PathTo(targetID string) ([]Transition, error)
  UnvisitedScreens() []string
  Coverage() float64 // % of discovered screens visited
  Export() GraphSnapshot // serializable for reports
  Screens() []ScreenNode
  Transitions() []Transition
}
// ═══ Video Processor ═══
type VideoProcessor interface {
  ExtractFrame(videoPath string, timestamp time.Duration) ([]byte, error)
  ExtractKeyFrames(videoPath string) ([]KeyFrame, error)
  DetectSceneChanges(videoPath string) ([]time.Duration, error)
  GenerateThumbnail(videoPath string, ts time.Duration, size Size) ([]byte, error)
}
// ═══ LLM Vision Provider ═══
type VisionProvider interface {
  AnalyzeImage(ctx, image []byte, prompt string) (string, error)
  CompareImages(ctx, img1, img2 []byte, prompt string) (string, error)
  SupportsVision() bool
  MaxImageSize() int
}
Two-Layer Analysis Pipeline
Layer 1: GoCV (Mechanical)
Fast, deterministic, no API calls
├─ Screenshot diffing
│  SSIM + pixel diff → change mask
├─ Edge detection
│  Canny edges → UI element bounds
├─ Color analysis
│  Dominant colors, contrast ratios
├─ Template matching
│  Find known icons/buttons
├─ Motion detection
│  Frame-to-frame delta for animations
├─ Contour detection
│  Bounding boxes for all UI elements
└─ Video frame extraction
   Key frames at scene changes
Layer 2: LLM Vision (Intelligent)
Contextual, semantic, requires API
├─ Screen identification
│  "This is the Settings page"
├─ UI comprehension
│  "Login form with email + password"
├─ UX issue detection
│  "Button text is truncated"
├─ Accessibility analysis
│  "Low contrast on header text"
├─ Navigation suggestions
│  "Click hamburger menu → Settings"
├─ Layout validation
│  "Content overlaps on small screen"
└─ Feature verification
   "Markdown preview matches docs"
GoCV runs FIRST (cheap, fast) → results fed as context to LLM Vision (expensive, smart)
e.g., "I detected 14 UI elements [bounding boxes]. Which is the Settings button?"
Key Data Types
// Screen analysis result
type ScreenAnalysis struct {
  ScreenID     string         // unique hash of screen state
  Title        string         // LLM-identified screen name
  Description  string         // what's on this screen
  Elements     []UIElement    // detected interactive elements
  TextRegions  []TextRegion   // OCR-detected text
  Issues       []VisualIssue  // detected problems
  Navigable    []Action       // possible navigation actions
  Timestamp    time.Time
}
type UIElement struct {
  Type       string    // button, input, link, menu, tab, etc.
  Label      string    // visible text or aria label
  BoundingBox Rect      // x, y, width, height
  Clickable  bool
  Confidence float64   // detection confidence 0-1
}
type VisualIssue struct {
  Type       string    // overlap, truncation, contrast, alignment, etc.
  Severity   string    // critical, high, medium, low
  Description string
  Region     Rect      // affected area
  Screenshot string    // annotated screenshot path
}
type ScreenDiff struct {
  Similarity   float64   // SSIM score 0-1
  ChangedRegions []Rect  // areas that changed
  NewElements  []UIElement // elements that appeared
  GoneElements []UIElement // elements that disappeared
  DiffImage    []byte    // visual diff overlay
  IsNewScreen  bool      // true if screens are fundamentally different
}

Key Design Decisions

  • Composite Analyzer — GoCV layer runs first (cheap, fast), feeds bounding boxes + diff data as structured context to LLM Vision layer. LLM gets "here are 14 detected elements at these coordinates" instead of raw pixels.
  • NavigationGraph — directed graph where nodes are unique screens (hashed by visual similarity) and edges are actions. Supports pathfinding (BFS) for "how do I get to Settings from here?" and coverage tracking.
  • Export formats — DOT (Graphviz), JSON, Mermaid for including navigation maps in QA reports and tickets.
  • VideoProcessor — GoCV-based frame extraction at scene changes (detects screen transitions automatically). Used by ticket generator to link video timestamps to issues.
  • Multiple VisionProviders — adapters for GPT-4o, Claude, Gemini, Qwen-VL. Provider selected based on LLMsVerifier scores. Fallback chain if primary provider fails.
