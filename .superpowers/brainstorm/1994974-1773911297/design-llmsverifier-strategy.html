Design Section 2: LLMsVerifier Strategy Extension

Interface-based Strategy pattern with RecipeBuilder for pluggable scoring

Strategy Pattern — Type Hierarchy
// ═══ Core Interfaces ═══
type ScoringStrategy interface {
  Name() string
  Description() string
  WeightConfig() WeightConfig
  CustomTests() []VerificationTest
  ScoreModel(ctx, ModelInfo, []TestResult) (StrategyScore, error)
  FilterModels([]ModelInfo) []ModelInfo
  MinimumThresholds() Thresholds
}
type VerificationTest interface {
  ID() string
  Name() string
  Category() TestCategory
  Run(ctx, LLMClient) (TestResult, error)
  Weight() float64
  Required() bool // fail-fast if required test fails
}
type RecipeStep interface {
  Apply(builder *StrategyBuilder) *StrategyBuilder
}
RecipeBuilder — Fluent API
// ═══ Builder Pattern ═══
strategy := NewStrategyBuilder("helix-qa").
  .WithDescription("Optimized for autonomous QA sessions").
  .WithWeights(WeightConfig{
    Responsiveness: 0.15, // less important for QA
    CodeCapability: 0.10, // not coding
    FeatureRichness: 0.15,
    Reliability: 0.20, // must be stable for long sessions
    VisionCapability: 0.25, // NEW: critical for QA
    InstructionFollowing: 0.15, // NEW: precise actions
  }).
  // Built-in recipe steps
  .WithRecipe(recipes.VisionTest()). // screenshot analysis test
  .WithRecipe(recipes.InstructionFollowingTest()). // action precision test
  .WithRecipe(recipes.ContextWindowTest(minTokens: 100000)).
  .WithRecipe(recipes.StreamingReliabilityTest()).
  .WithRecipe(recipes.LongSessionStabilityTest(duration: 30*time.Minute)).
  // Custom test
  .WithTest(&NavigationCommandTest{}).
  // Filters
  .RequireCapability("vision").
  .RequireCapability("streaming").
  .MinContextWindow(50000).
  // Thresholds
  .MinScore(0.6).
  .MaxLatency(10 * time.Second).
  .Build()
Implementations — Default vs QA Strategy
DefaultStrategy (existing behavior)
Weights:
  Responsiveness: 30%
  CodeCapability: 25%
  FeatureRichness: 25%
  Reliability: 20%

Tests: existence, responsiveness,
  latency, features, coding, errors

Filter: none (all models eligible)
Threshold: min score 0.0
QAStrategy (HelixQA injects)
Weights:
  VisionCapability: 25%
  Reliability: 20%
  InstructionFollow: 15%
  Responsiveness: 15%
  FeatureRichness: 15%
  CodeCapability: 10%

Tests: all default + vision test,
  instruction test, context window,
  streaming reliability, long session

Filter: must have vision + streaming
Threshold: min score 0.6

Backward Compatibility

The existing Verify() function without a strategy uses DefaultStrategy automatically. New VerifyWithStrategy(ctx, strategy ScoringStrategy) accepts custom strategies. All current tests continue to pass unchanged — DefaultStrategy produces identical scores to current behavior. The CalculateScores() method delegates to the active strategy's ScoreModel().
